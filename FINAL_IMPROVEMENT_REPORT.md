## УСТАНОВЛЕННЫЕ ПРИЧИНЫ МАССОВЫХ ОТКАЗОВ

### 1. Жесткая фильтрация источников по топикам (КРИТИЧНО)
**Проблема**: В `search.go` функция `selectRelevantSources()` использовала switch-case с жесткой фильтрацией.

**Пример**:
- Для топика `staff` возвращались только источники с `Kind == "general"`
- Страницы с `Kind == "teachers"` блокировались
- Результат: 0 фрагментов → шаблонный отказ

**Решение**: Заменена жесткая фильтрация на **scoring-систему**:
- Каждый источник получает баллы (score) на основе релевантности
- Источники сортируются по score
- Берутся топ-10 источников с наивысшим score
- Минимум 3 источника для fallback

### 2. Недостаточно источников данных
**Проблема**: Отсутствовали важные страницы сайта

**Решение**: Добавлены источники:
- `/sveden/grants/` (стипендии)
- `/sveden/vacant/` (вакантные места)
- `/sveden/employees/` (сотрудники)

**Удалены несуществующие** (404):
- `/students/practice/`
- `/students/retake/`
- `/students/schedule/`
- `/students/educational-resources/`

### 3. Слишком строгий промпт для LLM
**Проблема**: Промпт требовал дословного совпадения, запрещал объяснять

**Решение**: Улучшен промпт:
- Разрешено объяснять своими словами
- Разрешено обобщать факты из контекста
- Разрешены общие рекомендации на основе контекста
- Частичная информация → даем то, что есть
- Четкое разделение: вопросы о колледже vs вопросы вне темы

### 4. Недостаточный лимит токенов
**Проблема**: Для списка преподавателей limit=500 → ответ обрывался

**Решение**: 
- Преподаватели: 800 токенов
- Новости: 650 токенов
- Сравнения: 700 токенов
- Специальности: 500 токенов
- Обычные вопросы: 350 токенов

### 5. Слабая память диалога
**Проблема**: Бот не сохранял незавершенные вопросы при уточнениях

**Решение**: Добавлены поля в `DialogContext`:
- `PendingQuestion` - незавершенный вопрос
- `ExpectedParameter` - ожидаемый параметр (specialty, group, date)
- `PartialInfo` - уже собранная информация

Теперь при уточнении:
1. "Есть ли бюджетные места?" → бот запрашивает специальность
