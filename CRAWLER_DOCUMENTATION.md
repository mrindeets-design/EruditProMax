# Краулер сайта колледжа «Номос»

## Обзор

Краулер обходит веб-сайт колледжа, извлекает содержимое HTML-страниц и PDF-документов, и сохраняет их в базу данных SQLite для последующего поиска.

## Возможности

✅ **Реализовано:**
- Обход HTML-страниц с извлечением заголовков, текста и метаданных
- Обработка PDF-документов с извлечением текста
- Определение кодировки страниц (UTF-8, Windows-1251, ISO-8859-1)
- Обнаружение изменений по SHA-256 хешу содержимого
- Версионирование страниц и документов
- Защита от дубликатов (при повторном обходе не создаются новые записи)
- Ограничение обхода по домену (внешние ссылки игнорируются)
- Ограничение по глубине, количеству страниц и размеру файлов
- Параллельная обработка с настраиваемым количеством воркеров
- Обработка сетевых ошибок без потери данных
- Автоматическое создание фрагментов для поиска
- Корректная обработка относительных и абсолютных URL

## Архитектура

### Схема БД

**sources** - источники данных (сайты):
- `id` - первичный ключ
- `url` - базовый URL сайта
- `name` - название источника
- `enabled` - активен ли источник

**pages** - HTML-страницы:
- `id` - первичный ключ
- `source_id` - ссылка на источник
- `url` - полный URL страницы
- `title` - заголовок страницы
- `content_text` - извлечённый текст
- `content_hash` - SHA-256 хеш содержимого
- `version` - номер версии (инкрементируется при изменении)
- `indexed_at` - время индексации
- UNIQUE constraint по (source_id, url)

**documents** - PDF и другие документы:
- `id` - первичный ключ
- `source_id` - ссылка на источник
- `url` - полный URL документа
- `file_size` - размер файла в байтах
- `content_text` - извлечённый текст
- `content_hash` - SHA-256 хеш содержимого
- `version` - номер версии
- `indexed_at` - время индексации
- UNIQUE constraint по (source_id, url)

**fragments** - фрагменты для поиска:
- `id` - первичный ключ
- `source_id` - ссылка на источник
- `page_id` / `document_id` - ссылка на страницу или документ
- `content` - текст фрагмента (~500 символов)
- `position` - позиция в документе

### Логика обновления

1. **Новая страница/документ**: сохраняется с version=1
2. **Неизменённая страница**: content_hash совпадает → обновляется только indexed_at
3. **Изменённая страница**: content_hash отличается → version++, обновляются данные и фрагменты
4. **Сетевая ошибка**: данные в БД остаются без изменений

## Использование

### Командная строка

```bash
# Базовый обход
erudit.exe crawl -url https://nomos-edu.ru

# С настройками
erudit.exe crawl -url https://nomos-edu.ru -depth 3 -pages 100 -workers 4

# Параметры по умолчанию
-url       ""        # URL для обхода (обязательный)
-depth     2         # Максимальная глубина обхода
-pages     50        # Максимальное количество страниц
-workers   3         # Количество параллельных воркеров
-max-size  10485760  # Максимальный размер файла (10 MB)
```

### Из кода

```go
import "github.com/yourusername/erudit/crawler"

c := crawler.NewCrawler(db, crawler.Config{
    MaxDepth:     2,
    MaxPages:     50,
    MaxWorkers:   3,
    MaxFileSize:  10 * 1024 * 1024,
    AllowedHosts: []string{"nomos-edu.ru"},
})

stats, err := c.Crawl(context.Background(), "https://nomos-edu.ru")
if err != nil {
    log.Fatal(err)
}
```

## Ограничения и безопасность

### Реализованные ограничения

- **Домен**: обход только разрешённых хостов
- **Глубина**: по умолчанию 2 уровня от стартовой страницы
- **Количество**: по умолчанию максимум 50 страниц
- **Размер файла**: по умолчанию максимум 10 MB
- **Тайм-аут HTTP**: 30 секунд на запрос
- **User-Agent**: идентификация как "Erudit-Crawler/1.0"

### Защита от проблем

- **Дедупликация URL**: каждый URL обрабатывается только один раз за обход
- **Редиректы**: обрабатываются автоматически (до 10 редиректов)
- **Кодировка**: автоопределение UTF-8, Windows-1251, ISO-8859-1
- **Некорректный HTML**: graceful degradation, извлечение доступного текста
- **Сетевые ошибки**: не удаляют существующие данные
- **Concurrent access**: использование sync.Mutex для защиты shared state

## Производительность

### Рекомендации

- **Маленький сайт (<100 страниц)**: workers=2-3
- **Средний сайт (100-1000 страниц)**: workers=3-5
- **Большой сайт (>1000 страниц)**: workers=5-10

### Время обхода (приблизительно)

- 50 страниц: ~1-2 минуты (3 воркера)
- 100 страниц: ~3-5 минут (3 воркера)
- 500 страниц: ~15-30 минут (5 воркеров)

## Проблемы и решения

### PDF без текста (отсканированные)

**Проблема**: Текущий парсер использует простые регулярные выражения и не может извлечь текст из отсканированных PDF.

**Решение**: Для полноценной обработки потребуется OCR-библиотека. Пока такие документы помечаются как обработанные с пустым текстом.

### Windows-1251 кодировка

**Проблема**: Некоторые российские сайты используют устаревшую кодировку.

**Решение**: ✅ Реализована автоматическая конвертация в UTF-8.
