# Общий механизм обработки вопросов в Erudit

## Описание

Реализован универсальный механизм обработки вопросов о колледже, который не зависит от заранее заданных категорий вопросов и работает на новых темах и формулировках.

## Архитектура

### 1. Понимание вопроса и диалога (`intent.go`)

**Компоненты:**
- `Intent` - структура, содержащая понятое намерение пользователя
- `DialogContext` - контекст диалога с историей последних 5 шагов
- `UnderstandIntent()` - основная функция анализа вопроса

**Возможности:**
- Определение типа сообщения (greeting, question, clarification, topic_change)
- Определение темы (admission, payment, practice, contacts, staff, specialty, news, documents, life)
- Извлечение сущностей: специальность, группа, год, курс, форма обучения
- Извлечение условий: после 9/11 класса, льготы, дистанционно
- Распознавание анафор: "там", "это", "а сколько", "а какие"
- Разрешение ссылок на предыдущие реплики через контекст диалога
- Обнаружение явной смены темы
- Обработка разговорных формулировок, словоформ, опечаток

**Примеры:**
```
Вопрос: "Сколько стоит обучение на дизайнера?"
→ Тема: payment
→ Сущности: {specialty: "дизайн", specialty_code: "54.02.01"}

Вопрос: "А какие там экзамены?" (после вопроса о дизайне)
→ Тип: clarification
→ Тема: admission (унаследована)
→ Сущности: {specialty: "дизайн"} (из контекста)
```

### 2. Подготовка поиска (`search.go`)

**Компоненты:**
- `SearchQuery` - поисковый запрос с темой, сущностями и условиями
- `PrepareSearchQuery()` - преобразование интента в запросы
- `splitCompoundQuestion()` - разделение составных вопросов

**Возможности:**
- Преобразование вопроса с контекстом в самостоятельный поисковый запрос
- Разделение составных вопросов на подзапросы
- Не ограничивается фиксированными категориями

### 3. Поиск подтверждений (`search.go`)

**Компоненты:**
- `SearchMaterials()` - основной поиск по материалам
- `selectRelevantSources()` - динамический выбор источников
- `extractRelevantFragments()` - извлечение релевантных фрагментов
- `calculateRelevance()` - подсчёт релевантности

**Метод поиска:**
- **Лексический поиск**: по ключевым словам, сущностям, условиям
- **Тематический поиск**: проверка соответствия теме вопроса
- **Семантическое разбиение**: текст делится на смысловые фрагменты (параграфы)
- **Ранжирование**: по релевантности (0.0 - 1.0)

**Динамический выбор источников:**
- Главная страница всегда включается
- Источники фильтруются по теме вопроса
- При упоминании специальности добавляется её страница
- Учитываются заголовки, структура документов, метаданные

### 4. Проверка достаточности (`search.go`)

**Критерии достаточности:**
- Наличие минимум 2 фрагментов с релевантностью > 0.5
- Покрытие минимум 60% ключевых слов вопроса

**Повторный поиск:**
- Выполняется при слабых результатах (< 3 фрагмента)
- Использует синонимы: стоимость → цена/оплата, поступить → зачислиться
- Максимум 2 попытки

**Обработка отсутствия информации:**
- Если подтверждений нет: "На предоставленных материалах колледжа я не нашёл информации по этому вопросу."
- При противоречиях: указывается неопределённость

### 5. Формирование ответа (`answer.go`)

**Процесс:**
1. Понимание вопроса → Intent
2. Проверка неоднозначности → уточняющий вопрос если нужно
3. Поиск материалов → SearchResults
4. Проверка достаточности → повторный поиск если нужно
5. Подготовка контекста → топ-15 фрагментов
6. Генерация через Ollama → ответ
7. Обновление DialogContext

**Контекст для модели:**
- Топ-15 релевантных фрагментов
- С указанием источника и релевантности
- Компактный формат для экономии num_ctx

### 6. Кэширование и скорость

**Оптимизации:**
- `num_ctx`: 32768 (увеличено с 8192)
- Ollama timeout: 90 секунд (было 20)
- Streaming для мгновенного отображения

**Измеренные задержки:**
```
CACHE HIT: ~10ms
CACHE MISS: 5-18 секунд
  - Понимание: ~1ms
  - Поиск: 50-500ms
  - Ollama: 5-17 секунд
```

## Реальные цепочки обработки

### Пример 1: Стоимость обучения

```
ВОПРОС: "Сколько стоит обучение на дизайнера?"

1. ПОНИМАНИЕ:
   Intent: {Type: "question", Topic: "payment", 
            Entities: {specialty: "дизайн", specialty_code: "54.02.01"}}

2. ПОИСК:
   Источники: главная, поступающим, /abitur/specialties/54.02.01/
   
3. РЕЗУЛЬТАТЫ:
   Фрагмент 1 (rel=0.85): "Стоимость обучения по специальности 54.02.01..."
   Фрагмент 2 (rel=0.72): "Графический дизайн - очная форма 120 000 руб/год..."

4. ДОСТАТОЧНОСТЬ: ✓

5. ОТВЕТ: "Стоимость обучения по специальности 54.02.01 «Дизайн» 
          составляет 120 000 рублей в год при очной форме обучения."
```

### Пример 2: Продолжение диалога

```
Q1: "Расскажи про специальность дизайн"
→ Context: {CurrentTopic: "specialty", LastEntities: {specialty: "дизайн"}}

Q2: "А сколько стоит?"

ПОНИМАНИЕ:
   Intent: {Type: "clarification", Topic: "payment",
            Entities: {specialty: "дизайн"},  // из контекста!
            Anaphora: ["а сколько"]}

ПОИСК: "сколько стоит дизайн"  // обогащён контекстом

ОТВЕТ: (аналогично примеру 1)
```

### Пример 3: Неоднозначный вопрос

```
ВОПРОС: "Сколько стоит?"

ПОНИМАНИЕ:
   Intent: {Topic: "payment", Entities: {},  // нет специальности!
            IsAmbiguous: true, Confidence: 0.3}

ОТВЕТ: "Уточните, пожалуйста, о какой специальности идёт речь."
```

**`/api/chat`:**
- Проверка кэша → GenerateAnswer() → Сохранение в кэш

**`/api/chat/stream`:**
- Проверка кэша → StreamAnswer() → SSE streaming → Сохранение в кэш

## Проверка

### Тестовые темы

✅ Поступление, оплата, практика, документы, контакты, сотрудники, студенческая жизнь
✅ Перефразировки, продолжение диалога, смена темы
⏳ Вопросы без подтверждённого ответа

### Непроверенные области

⚠️ Требуют ручной проверки:
- Сложные составные вопросы (3+ подвопроса)
- Глубокие анафоры (ссылки через 3+ хода)
- Противоречивые условия
- Редкие темы (не в топ-10)
