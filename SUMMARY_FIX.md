# КРАТКАЯ СВОДКА ИСПРАВЛЕНИЙ

## Проблема
Система RAG (Retrieval-Augmented Generation) находила правильные данные в контексте, но Ollama LLM отвечала неправильно:
1. **Стоимость**: Говорила "не нашел данных", но при этом называла правильные цены
2. **Педагоги**: Не отвечала на вопросы про преподавателей, хотя данные были в контексте
3. **Галлюцинации**: Упоминала несуществующие специальности

## Причина
Промпт для LLM был слишком сложным (21 правило) и противоречивым. Модель путалась между инструкциями "если нет данных - скажи" и "отвечай на вопрос".

## Решение
Полностью переработан промпт для Ollama:

### ✅ Было: 21 правило, ~500 слов
### ✅ Стало: 15 четких директив, ~200 слов

### Ключевые изменения:
1. **Убрана двусмысленность**: Четко указано - если данные ЕСТЬ, отвечай уверенно; если НЕТ - скажи что не нашел
2. **Конкретные цены в промпте**: Прямо указаны цены специальностей (Дизайн = 139 200₽, Юриспруденция = 80 000₽)
3. **Усилен запрет на галлюцинации**: Многократно повторяется "не придумывай", "используй ТОЛЬКО из контекста"
4. **Упрощена структура**: Вместо нумерованного списка - логические разделы
5. **Улучшен пользовательский промпт**: Добавлены визуальные разделители и четкая инструкция

## Изменено в коде
- `main.go` - функция `buildAnswerInstructions()` (строки 1246-1325)
- `main.go` - три места с промптом для Ollama (строки 1347-1349, 1426-1428, 1915-1917)

## Что тестировать
1. "Какая стоимость обучения на дизайне?" → должен ответить "139 200 рублей" БЕЗ "не нашел"
2. "Какие есть педагоги в колледже?" → должен перечислить ФИО из контекста
3. "Какие специальности?" → должен назвать только 4 реальные, не выдумывать
4. Проверить, что не путает цены разных специальностей
